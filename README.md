# BossCoding

> 你是老板：需求你说，制度盯人。

**给 AI 协作项目的开发流程地基，专为不会写代码的人设计。**一条命令，把一套经过真实项目打磨的公司制度装进你的新项目：规则文件、机器守卫、云端质检、决策档案、交付流程。之后你只做老板该做的事——说需求、看效果、做决策；写码、测试、自检、提交、过检、排队、合并，全由你雇的 AI 按制度完成，并且边干边用大白话向你汇报每一步在做什么。

不挑你雇哪家：Codex、Claude Code、Kimi Code、Qwen Code、Cursor、GitHub Copilot、Trae、CodeBuddy、通义灵码、Gemini CLI、iFlow 读到的是同一份制度。

## 开始之前只要一样东西

电脑上装了 Node.js 18.17 或更新版本（AI 编程工具基本都自带；不确定就在终端里跑 `node -v`，报「命令找不到」就去 [nodejs.org](https://nodejs.org) 下载安装，一路下一步即可）。

## 三步开始（不需要会写代码，也不需要先买任何东西）

先建一个只放这个产品的新文件夹，进去之后：

```bash
npx bosscoding init
```

```bash
npm install
```

然后对你的 AI 说：**「读一遍 AGENTS.md。之后需求我说，规矩你守。」**

任何时候不知道自己在哪一步、下一步该干什么，跑 `npx boss status`，它只看不改。

第一次对话，AI 只会问你一句话：「你想做个什么？」——不问域名、不问服务器、不问备案。说出你的想法，当天就能在自己电脑上看到它跑起来。

## 老板的一天（日常只有三句话）

| 你说 | 底下人做 |
|---|---|
| 「开个新任务：××」 | AI 跑 `npx boss task ××`，开出独立工作区并把工具装好，互不打架；你把新文件夹拖进一个新的 AI 对话窗口，接着说需求 |
| （任务干完时）什么都不用说 | AI 必须交**验收单**：怎么打开看、重点看哪三点、不满意怎么说。你没验收，任务不算完 |
| 「可以，合并」 | AI 跑 `npx boss merge` 排队（并行干活、串行合并），过完云端质检才进主干 |

测试、代码规范、提交格式、合并次序——这些词你永远不需要主动想起，制度和守卫替你盯着。

## 从想法到上线：四阶梯

产品长大需要的基建（备份、服务器、域名），框架按「四阶梯」**渐进式触发**：每样东西在你真正需要它的那一刻才出现，出现时 AI 会用大白话讲清它是什么、多少钱、谁来办。你永远不会在看到自己的产品跑起来之前，被要求去注册或购买任何东西。

- **第 0 阶・开工**：说想法 → 本地跑起来 → 验收。可以在这一阶迭代任意久。
- **第 1 阶・GitHub（免费）**：AI 第一次埋头干活的空档，你顺手注册个账号（约十分钟）；第一次验收通过后 AI 代办连接与推送。从此代码有异地备份，云端质检口自动亮起——地基 init 时就埋好了，接通即用。
- **第 2 阶・服务器（约 ¥99–199／年）**：当你说「想给朋友用」，AI 帮你选一台轻量服务器（先问一句用户在国内还是海外，节点不买错），付钱你来、配置部署 AI 包办。朋友当天就能通过 IP 地址访问。
- **第 3 阶・域名（几十块／年）**：当你说「想要自己的域名」，国内路线 AI 陪你注册域名、提交 ICP 备案（法定流程，约一到两周，期间朋友照旧用 IP，开发照常）；海外路线直接解析。之后 HTTPS 证书 AI 代办。

一开始就明确要做正式上线的产品？告诉 AI，它会建议把后两阶提前启动——备案是全程最慢的一站，早递交早省事。做的是纯本地小工具？梯子到第 1 阶为止，服务器和域名永远不会来烦你。完整裁决见 [docs/decisions/2026-07-27-progressive-ladder.md](docs/decisions/2026-07-27-progressive-ladder.md)。

## 装了什么

| 文件 | 是什么 |
|---|---|
| `AGENTS.md` | 规则文件：AI 的行为规则真身。含**导师模式**（AI 必须用比喻和大白话向你解释一切）、干活流程、验收单、红线清单 |
| `CLAUDE.md` | 给 Claude Code 的门牌，一行导入指向规则文件——规则永远只有一份 |
| `npx boss status` | 状态盘：我在四阶梯的哪一阶、干活环境齐不齐、下一步该干什么。只看不改，看不懂就先跑它 |
| `npx boss check` | 9 项守卫：密钥不进代码（连还没提交的文件也扫）、.env 必须被忽略、脚本可执行位、规则单一真身、规则不膨胀、文档无死链、决策记录五节齐全、无裸待办、CI 配置不踩已知的坑。违反就红 |
| `npx boss task <任务名>` | 并行按钮：一条命令开出独立工作区＋任务分支，把新文件夹拖给新的 AI 会话就是一条并行生产线 |
| `npx boss merge` | 排队判定：多个 AI 并行时，问一句「现在轮到我合并了吗」。答案由 PR 号定，不由谁先问定 |
| `.github/workflows/bosscoding.yml` | 质检口：每次改动申请（PR）自动跑守卫＋项目的冒烟测试，不过检不进主干。连上 GitHub 前安静待命 |
| `docs/decisions/` | 决策档案室：「当初为什么这么定」只追加、不修改 |
| 三个 git hook | 本地门禁：并行时主工作区只跑主干（单人单工作区时一声不吭）；禁止直推主干——GitHub 免费版私有仓库开不了分支保护，这道 ¥0 的闸补上它 |
| `.agents/skills/` 与 `.claude/skills/` | 两个技能：**boss-flow** 教 AI 按「分支 → 自检 → Draft PR → 排队 → 合并 → 验收单」交付；**boss-ladder** 教 AI 按四阶梯在正确的时机推进基建 |
| `.gemini/` 与 `.iflow/` | 两行配置，让 Gemini CLI 与 iFlow 也认同一份规则文件 |

## 它的四条设计原则

1. **约束力压在质检口上，不压在 AI 的自觉上。**各家 agent 能力参差，但「会读规则文件、会跑命令」人人都会；真正的强制在 CI（云端质检）与本地 git hook——不管你雇的哪家 AI，改动都过同一道检。
2. **基建渐进式触发。**免费且当天生效的（GitHub），第一天顺手办掉；花钱的、要等审批的（服务器、域名、备案），等你的需求自己冒出来再出现。正反馈永远排第一。
3. **规则要么是机器查的，要么是有日期的裁决，要么别写。**能执行的规则住在守卫里（违反就红）；「为什么这么定」住在决策档案里（只追加）；现状靠跑命令看。散文文档注定腐烂，所以尽量不写散文。
4. **出了事故，先撤销修复，不是加流程。**新增任何一道门禁的前提：它挂着一次真实发生过的事故，并且同时删掉一道旧的。框架自带反过度治理的免疫系统。

## 常见问题

**完全不会代码，真能用吗？**能，这正是设计目标。你负责三件事：说清想要什么、亲眼验收、对花钱和上线的事点头。规则文件里的导师模式强制 AI 用大白话和比喻向你解释每一个术语。

**必须有 GitHub 吗？**开工不需要。本地阶段分支照开、自检照跑、合并在本地做（`npx boss merge` 会告诉你不用排队）。连上 GitHub 后，备份与云端质检自动生效——AI 会在合适的时机主动带你走这一步。

**为什么禁止直推主干？**主干是你产品「永远能跑」的那个版本。所有改动先过质检再进主干，改坏了扔掉分支重来就是，主干永远是稳的。有本地门禁和云端质检两道闸盯着，不靠任何人的记性。

**AI 会不会背着我花钱、上线、删东西？**规则文件把这些列为红线：先说明、等你确认、再动手。发布类动作（对外发版、公开仓库）永远不许自动化。你说「改坏了，退回去」时，AI 会先把可选的时间点念给你听，再用只增不减的方式撤销——不会抹掉你的东西。

**测试是怎么回事，我需要管吗？**不需要你管，但你需要知道它在保护什么。守卫查的是卫生（密钥有没有泄露、规则有没有分叉），查不出「登录页坏了」。所以规则要求 AI 给你的项目建一条**冒烟测试**——一条「产品还能不能跑起来」的最小自动检查，之后每次改动都跑一遍。框架不替你写它，因为每个产品该测什么各不相同；框架只负责逼着 AI 建、并在质检口上跑。

**不想用了怎么退出？**删掉 `AGENTS.md`、`CLAUDE.md`、`.github/workflows/bosscoding.yml`、`.agents/`、`.claude/skills/boss-*`、`docs/decisions/`，再删掉 `.git/hooks/` 下的 `pre-commit`、`post-checkout`、`pre-push` 三个文件，最后从 `package.json` 里移除 `bosscoding` 依赖。你的代码一行不受影响——这套东西全都长在代码外面。

**装完之后框架怎么升级？**守卫与工具的逻辑住在 `bosscoding` 包里，你的项目只有一行版本引用；维护者发布改进后，你的项目下次跑质检自动用上。新加的检查先以黄色提醒跑满一个版本、看清误报率，下一版才转硬拦——你有一个版本的时间从容处理。你的 `AGENTS.md` 是老板的规则，任何更新永不改写它；`npx boss update` 只刷新框架管理的文件（CI／决策模板／技能／git hook），重新 clone 后跑一次它即可补回 git hook。

## 维护者须知

- 运行时零第三方依赖（只用 Node 标准库），`node --test` 跑单测，`node bin/bosscoding.mjs check` 自检。
- 结构：`bin/`（命令入口）、`lib/guards/`（9 项守卫）、`lib/commands/`（init／status／check／task／update／merge）、`lib/hooks.mjs` 与 `lib/skills.mjs`（git hook 与技能安装）、`templates/`（写进用户项目的全部资产）。
- 立法与发布纪律见 [AGENTS.md](AGENTS.md)；范围与形态的裁决理由见 [docs/decisions/2026-07-26-v1-scope.md](docs/decisions/2026-07-26-v1-scope.md)。
