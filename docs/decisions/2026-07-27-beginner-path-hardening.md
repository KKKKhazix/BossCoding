# 小白路径上的每一次失败都必须自解释或自愈（2026-07-27）

## 影响

- 之前：一次以小白身份的完整实测（空目录装到开并行任务、连 GitHub、私有仓库）挖出一串各自独立的坑：新工作区没有依赖，第一条自检命令就以 `boss: command not found` 告败；缺依赖时按规则跑 `npx boss check` 会去 npm 下载一个**陌生人的同名包**（`boss@1.0.5` 真实存在），结果是守卫根本没跑而屏幕上看不出来；私有仓库（正是四阶梯教他建的）让 `boss merge` 必然失败，提示是「设环境变量 GITHUB_TOKEN」；在桌面或家目录里 init 会一声不吭地把私人文件夹变成版本库；中文文件夹名让项目名变成七个连字符（npm 非法名）；技能入口以软链提交，Windows 上克隆即失效。
- 之后：这些位置要么自己修好（新工作区自动装依赖、`boss merge` 自动取用 `gh` 的通行证、技能改成真实副本），要么在失败的那一句话里说清下一步（拒绝在家目录开工并给出建文件夹的命令、非 GitHub 远端改为说明而非红叉）。

## 根因

这些坑看着零散，其实是同一条纪律的缺口：**框架此前只保证「按正确路径走会顺」，没保证「走岔了会被接住」**。而目标用户的特征恰恰是不知道哪条是正确路径——他们撞上的第一句话，往往就是他们对这套框架的全部印象。

其中最危险的一个（`npx boss` 落到陌生人的包上）暴露了更深的一层：**框架给出的命令，在环境不齐时会静默地做另一件事**。它不报错、不停下，只是没做该做的事。这与决策档案里那条既有纪律同源——不把两种含义不同的失败压成同一个空结果。

## 裁决

**小白路径上的每一处失败，必须落进三档之一：能自愈的当场自愈（`boss task` 补装依赖、`boss merge` 自动取 `gh auth token`、技能写真实副本而非软链）；不能自愈但能说清的，在失败那一句里给出可照抄的下一步（家目录拒绝开工、本地门禁按处境给两种救法、私有仓库提示改成「跑一次 gh auth login」）；既不能自愈也无从判断的，交回给人并明确放行（远端不在 GitHub 时说明情况后返回 0，不拿红叉挡住单干的人）。**配套：自检命令在所有文案里统一为 `npm run preflight`，短名 `npx boss` 不再出现在任何教用户敲的位置；`init` 结尾的指引不得在有待处理事项时承诺「应当全绿」。

## 被否决的方案

**「在文档里写清这些坑」**：文档解决不了「用户不读文档」这个根因，而且这些坑里有一半（陌生包、软链失效）的现象根本不指向原因，读者就算读过文档也对不上号。

**「`boss task` 之外也全面自动装依赖（比如 check 前自动装）」**：把网络动作藏进只读命令，会让一条本该秒回的检查在弱网下卡住几分钟，且违反 status／check 的只读契约。装依赖只发生在明确的建设动作里（开任务）。

**「把短名 `boss` 从 bin 里删掉，只留 `bosscoding`」**：短名在装好依赖的项目里工作正常且更好敲，删掉是因噎废食；真正的问题是「教用户敲的位置」用了它，改文案即可。

**「拒绝在任何『文件很多』的目录里 init」**：会误伤「已经做了一周、现在想接入框架」这条重要路径（那种目录本来就文件很多）。判据换成位置本身（家目录、磁盘根、桌面／文档／下载这类系统文件夹），不看文件数。

## 不变量

1. 框架给出的任何命令，在环境不齐时必须显式失败或自愈，永不静默地做另一件事——`npx boss check` 落到陌生包上是这条的反面教材，因此教用户敲的自检命令一律是 `npm run preflight`。
2. 拒绝执行时必须给出可照抄的下一步命令；只说「不行」不算合格的拒绝（测试盯着家目录这一条）。
3. 写进用户项目的框架资产不得依赖软链——判据：把仓库在 Windows 上克隆一份，全部资产仍然有效。
4. 失效条件：若某处自愈行为本身成为新的失败源（例如自动装依赖在弱网下频繁挂住 `boss task`），退回到「明确提示 + 一条可照抄的命令」，而不是继续加自动化。
