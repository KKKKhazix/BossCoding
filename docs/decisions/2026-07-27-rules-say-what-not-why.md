# 规则文件只写「做什么」，「为什么」留在 decisions（2026-07-27）

（对应 issue #11。）

## 影响

- 之前：规则文件里每条规则都夹带一段「为什么」的论证。上游实测：文件膨胀到 4000 字符后开始**自相矛盾**——相邻两行，一条教人 `gh pr ready && gh pr merge --auto`，下一条说「不是自己 `gh pr ready`」。agent 读到哪条全看运气。
- 之后：规则模板多一句写作纪律；`rules-budget` 守卫多一条单行上限（>500 字符提醒）。上游按这条纪律瘦身的实测结果：4000 字符 → 2400（−39%），最长一行 662 → 433，那对互相矛盾的规则随之消失。

## 根因

那些论证已经完整存在于 `docs/decisions/` 里，规则正文自己还链接着它们——**同一件事写两遍，长的那遍压着短的那遍**。膨胀于是不只是「难读」，它会产生错误指令：两遍之间一旦不同步，规则文件里就出现两条打架的规矩，而没有任何机器能判断该听哪条。

为什么用「行长」当抓手：自相矛盾查不了，重复论证也查不了，但「一条规则写了 662 个字符」是它最稳的症状——那么长的一行几乎必然是「结论＋论证」挤在一起。它是症状不是病因，所以只提醒、不硬拦。

## 裁决

**规则文件（AGENTS.md）只写「做什么」，「为什么这么定」一律留在 `docs/decisions/`，正文最多留一句结论。这句纪律写进规则模板本身；单行超过 500 字符由 `rules-budget` 守卫出声提醒。**

## 被否决的方案

**「按上游的数字把体积预算收紧到 2400 字符」**：上游那个数字是在那个仓库、那些业务规则上测出来的，照搬等于把别人的实测冒充通用结论——恰好违反本框架「凭实测不凭感觉」的原则。更要命的是收紧预算会让一批现有用户的 CI 当场变红（见 `2026-07-27-new-checks-land-as-warnings.md`）。体积预算维持 200 行／10KB 不动。

**「守卫直接查『规则文件里有没有为什么』」**：想过用「因为／由于／原因是」之类的词去抓论证。中文里这些词在正常句子里到处都是，误报率高到无法使用。

**「只写进模板，不加任何检查」**：这正是事故前的状态——纪律写在纸上，膨胀照样发生。至少要有一个会出声的东西。

## 不变量

1. 规则文件里出现「为什么这么定」的完整论证，就是它放错了地方；正确的位置是 `docs/decisions/`，正文只留结论。
2. 行长检查是症状检查，永远只提醒不硬拦——一行长不代表写错了，只代表值得看一眼。
3. 体积预算（200 行／10KB）的任何收紧都必须先推翻本篇，并按新检查的宽限期规则走。
4. 失效条件：若规则文件在遵守本纪律的前提下仍长出自相矛盾的相邻两条，说明抓手选错了，届时按那次真实矛盾重新找判据。
