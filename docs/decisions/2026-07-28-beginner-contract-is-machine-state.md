# 小白体验承诺必须由机器状态证明（2026-07-28）

## 影响

- 之前：第一次使用要先理解命令、版本库和 GitHub；已有规则文件时可能只装上一半却显示成功；「有远端地址」也会被说成「已有异地备份」。
- 之后：老板只向 AI 说产品想法；安装、任务、验收收尾和升级都由 AI 代办；状态只陈述命令能证明的事实。

## 根因

2026-07-28 用全新电脑心态实走全旅程，发现入口把工具命令当成用户流程，状态又把「已配置」推断成「已完成」。这些推断在没有首个提交、没有推送、缺本地门禁或已有普通 AGENTS.md 时都会给出假绿。

## 裁决

**把 BossCoding 设计成 AI 操作、老板验收的工作台；每一句完成承诺都必须对应可复查的机器事实。**

具体执行：

1. 首次入口只要求老板把一段话交给 AI，命令只作为 AI 的操作说明和人工备用。
2. `status` 分开报告本地提交、远端配置、真正上传、依赖、本地门禁、产品文件和最小运行验证，不再用一个地址代替完成状态。
3. `task` 必须拒绝带未保存改动的仓库；`finish` 在验收后负责自检和安全合并，不把切目录、拼命令、删工作区交给老板。
4. `update` 必须真的升级本地包并刷新框架文件；不能在未安装项目里假装成功，永不改写老板的 AGENTS.md。
5. `check` 只承诺协作地基通过；没有产品时必须明说，不把守卫全绿说成产品完成。

## 被否决的方案

**「写一篇更详细的教程」**：教程仍要求老板理解并记住版本库、工作区和合并，不能阻止命令在错误目录写文件，也不能让状态变真。

**「让 AI 自由判断项目状态」**：换一个对话就会丢失记忆，同一仓库可能得到不同答案；可运行命令比对话记忆稳定。

**「自动覆盖已有规则来保证完整」**：会抹掉老板原有制度。正确做法是拒绝假装完成，并让 AI 合并两边规则。

## 不变量

1. 帮助命令只读；普通非空文件夹不被静默改造成项目；已有产品可在保留内容的前提下接入。
2. AGENTS.md 与 CLAUDE.md 永不由更新命令覆盖；规则缺失时检查必须变红。
3. 「已上传」「已安装」「已合并」「可运行」分别由对应命令结果证明，不能互相代替。
4. 本地收尾只允许在主干干净且任务可快进时执行；有远端的项目不代替老板上传、开申请单或上线。
5. 若完整黑盒旅程不能从空目录走到本地验收并安全收尾，本裁决视为未落实。
