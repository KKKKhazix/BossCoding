# 禁止直推主干：pre-push 本地门禁（2026-07-27）

## 影响

- 之前：规则文件写着「禁止直推 main，所有改动走 PR」，但 GitHub 免费版的私有仓库开不了分支保护（2026-07 实查官方文档：分支保护与 rulesets 对免费版仅限公开仓库；私有仓库要 Pro，约 ¥29／月）。也就是说，不花钱的小白项目里这条规则没有任何机器执行，全靠 AI 自觉——恰好违反本框架设计原则第一条「约束力压在质检口上，不压在 AI 的自觉上」。
- 之后：`init`／`update` 装 pre-push hook，直推已存在的远端主干被本地拦下；¥0 成本拿到分支保护的主要效果。

## 根因

挂的真实事故：上游教程作者的实战经验——没有分支保护时，「你或者你的 Agent 随时可能手一抖，直接把有问题的代码推到主分支上，然后线上直接崩掉」（教程第 15 步原文），这正是他花 ¥29／月买 Pro 的唯一理由。框架的目标用户是不想（或不该被要求）花这笔钱的小白，而免费方案里唯一能立门禁的位置就是本地 pre-push。

## 裁决

**pre-push hook 只拦「三件事同时成立」的推送：推往 origin ＋ 目标是主干 ＋ 远端主干已存在。**因此天然放行：首次推送建立远端主干（此时没有「绕过质检」可言）、推功能分支、推非 origin 的远端（备份镜像）。逃生阀用 git 内置的 `--no-verify`，不另造旁路；CI 环境（`$CI` 非空）直接放行——CI 里的推送是流程自己的动作。买 Pro 开真正的分支保护降级为可选增强，不是前提。

## 被否决的方案

**「要求用户买 GitHub Pro」**：¥29／月对「先试试看」的小白是真实门槛，且教程实测表明多数人会跳过这步——跳过后规则就成了墙上的字。

**「只警告不拦」**：pre-push 触发时推送已在进行，警告等于没有——主工作区 hook 的分工先例（切分支时改正成本为零所以只提醒；真要提交时硬拦）在这里只剩「硬拦」一个有意义的档位。新检查以 warn 进场的纪律（2026-07-27-new-checks-land-as-warnings）管的是 `boss check` 的退出码会改红别人的 CI；本 hook 不进 CI、拦的是规则文件从 v1 就明文禁止的动作，且首推豁免消掉了已知误报面。

**「拦所有远端」**：把整仓推去备份镜像（`git push backup main`）是合法动作，拦它是纯误报；事故类别是「手一抖推上正式主干」，正式主干在 origin。

## 不变量

1. 首次推送建立远端主干必须放行（测试盯着）——否则四阶梯第 1 阶「连接 GitHub」会被自己的门禁拦死。
2. 本 hook 挡意外不挡故意：`--no-verify` 永远可用，且提示语里明说。删掉 hook 文件即停用，BossCoding 不偷偷装回。
3. 失效条件：若 GitHub 向免费版私有仓库开放分支保护／rulesets，本 hook 降级为「没开分支保护时的兜底」，提示语随之改写；若真实用户中出现首推之外的成规模误报场景，按实例收窄拦截条件。
