# 串行合并从约定升级为一条命令（2026-07-27）

（对应 issue #2。该 issue 原本挂着「等第一个真实用户撞车再做」的触发条件，本篇提前执行并说明理由。）

## 影响

- 之前：「转 Ready 前先确认没有别的 PR 在排队」是一句约定，靠人或 agent 自己看一眼。上游实测：两条并行的活相隔 **57 秒**各自查到「队列为空」，双双转 Ready，一个 PR 因此连跑 **3 次** CI，另一个在门口停了 **12 分钟**。
- 之后：`npx boss merge` 给出判定与退出码（0 ＝ 轮到你，1 ＝ 还没轮到），规则模板与开工技能都改成跑这条命令。上游工具化后用它自己完成了自身合并：1 轮，零重跑。

## 根因

约定必然输给竞态，因为「队列此刻空不空」是**瞬时状态**：查询与动作之间有时间窗，两个人在窗内各自看到的都是真的，合起来就是错的。

换判据就解决了：问的不再是「现在有没有人」，而是「我是不是号最小的那个」。PR 号由 GitHub 原子分配、单调递增，构成全序，任何人在任何时刻算出的赢家都一致（面包店取号法）。同一件事从随时间抖动的状态，变成了不抖动的事实。

至于为什么不再等真实用户撞车：这道机制的触发前提在本仓库自己身上已经成立——同一版里刚为「多个 agent 挤在一个工作区」装了 git hook（见 `2026-07-27-main-worktree-only-main.md`）。承认并行会发生，却只给并行装半套护栏，比两套都不装更糟。

## 裁决

**新增第四个命令 `boss merge`：读 GitHub 上的未合并 PR，按号排队，回答「现在轮到我了吗」。只读——不转 Ready、不合并、不写任何 GitHub 资源；判定通过退出码给出，合并动作永远由人或 agent 显式执行。队头超过 15 分钟没动静按弃权跳过，且弃权放行后不再回头做抢占确认。**

## 被否决的方案

**「让它顺手把 PR 合了」**：判定与执行合在一起最省事，但合并是不可逆的，而这条命令要装进所有用户项目、被各家 agent 自动调用。只读的工具误用了最多是白等一轮；会写的工具误用了是别人的主干。只读还有一个附带好处：公开仓库不带任何令牌就能用。

**「继续等第一个真实用户撞车」**（issue #2 原定的触发条件）：事故驱动立法防的是凭想象加机制，而这条的事故已经真实发生过（上游实测，数字在上面），只是发生在维护者身上而非用户身上。同一版已经为并行装了工作区护栏，缺这一半会让那一半失去意义。

**「把队列判定做进 CI」**：CI 里判定要给写权限才能改 PR 状态，且每次判定都要烧一次 workflow 额度。本地一条命令、一次接口调用就够。

**「用『谁先抢到锁』而不是『谁号最小』」**：需要一个所有 lane 都信任的外部状态存放处（issue、分支、第三方服务），全都要写权限，且锁会泄漏——持锁方崩溃就永远卡住。取号法不需要写任何东西，弃权规则就是它的自愈机制。

**「弃权后重新确认自己是不是最小」**：看起来更严谨，实际是死循环——被放行的一方每轮都会重新发现「前面还有个号更小的僵尸」，永远轮不到自己。所以弃权判定必须豁免随后的抢占确认，有测试盯着这条。

## 不变量

1. `boss merge` 永不写 GitHub：不转 Ready、不合并、不评论。判定与执行分离是它敢被自动调用的全部前提。
2. 排队判据是 PR 号的全序，不是「查一眼队列空不空」。任何改成看瞬时状态的改动都要先推翻本篇。
3. 弃权放行之后不再做抢占确认（否则死循环），有测试盯着。
4. Draft PR 不占队列：还没送检就不算在排队。
5. 失效条件：若出现「15 分钟弃权阈值放行了实际仍在推进的 PR」的真实案例，按那次的真实耗时重估阈值，而不是凭感觉调大。
