# 命名：BossCoding（2026-07-26）

## 影响

- 之前：项目名「规矩（guiju）」——说教味重、对国际用户不可读、无传播欲；老板（本项目的产品负责人）直评「太扯淡」。
- 之后：BossCoding——身份翻转式命名：用户不是「守规矩的学徒」，是「发号施令的老板」。自带传播话术「别 vibe coding 了，来 boss coding」；npm 上 bosscoding／boss-coding／bosscode 三个变体当日实查全部无人占用，GitHub 仅两个零星标同名空仓库。

## 根因

命名卖动作不如卖身份。备选的 kaigong（开工）、kaopu（靠谱）、shangdao（上道）、xinshoucun（新手村）全部站在「项目／工人」视角；BossCoding 站在「用户自我感觉」视角——目标用户（不会写代码的人）不想当小白，想当老板。且本框架的实质恰好支撑这个名字：守卫是质检部、CI 是生产线、决策档案是公司制度，老板只说需求。

## 裁决

**npm 包名 `bosscoding`，品牌写法 BossCoding，日常短命令 `boss`。**

## 被否决的方案

**「guiju（规矩）」**：中文有训人味，拼音对英文用户不可读，双端皆弱。
**「kaigong（开工）」**：动作绑定与「开工大吉」梗俱佳，但需要讲文化故事才被非中文用户理解；身份感为零。
**「kaopu／shangdao／xinshoucun」**：各有单点长处（价值主张直给／双关／小白心智），但或命令感弱、或方言色彩重、或音节过长，均不及身份翻转的传播力。
**「luban（鲁班）／kaiju」**：npm 已被占用，直接出局。

## 不变量

1. 短命令 `boss` 只在已安装的项目内使用；一切安装与首次场景的文档必须写全名 `npx bosscoding`——项目外裸跑 `npx boss` 会解析到 npm 上他人的同名包。
2. 品牌展示恒为 BossCoding，包名与命令恒为全小写；两者不混用。
3. 若日后出现同名商标纠纷或 npm 包名仲裁，改名成本 = 本次改名的实际工作量（约一小时），届时按当时事实重估，不预设防御性抢注。
