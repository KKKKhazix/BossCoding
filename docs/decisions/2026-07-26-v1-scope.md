# v1 范围与形态（2026-07-26）

## 影响

- 之前：这套流程框架长在上游 aihot 仓库体内，与业务纠缠（29 个守卫里只有 8 个通用、规则文件里元规则与业务红线混写），外人整仓下载也拆不出能用的部分。它只服务一个人。
- 之后：任何人在空目录跑一条 `npx guiju init`，得到规则文件（AGENTS.md）、8 项守卫、CI 质检口、决策档案与开工技能；实查十家主流 coding agent（Codex、Kimi Code、Qwen Code、Cursor、Copilot、Trae、CodeBuddy、通义灵码直接认，Claude Code 走门牌，Gemini／iFlow 走配置）全部吃到同一份规则。

## 根因

2026-07-26 全网实查得到三个决定形态的事实：

1. 插件（plugin）是 Claude Code 的私有安装协议，Codex、Kimi、Qwen、Cursor 等一概不认；而目标用户（用 AI 写代码的中文新手）约一半不用 Claude Code。把主体压在任何一家的私有通道上，覆盖面天然残缺。
2. 与 agent 无关的三样东西是全生态最大公约数：AGENTS.md 规则文件（开放标准，Linux 基金会托管，6 万＋项目在用）、项目内脚本、GitHub Actions。各家 agent 能力参差（有的没有 hooks、有的不会主动自检），约束力必须压在 CI 上——不管店里雇哪家厨师，菜都过同一道质检口。
3. 分发上，npm 有阿里官方全量国内镜像（10–15 分钟同步一轮），GitHub 没有任何官方国内镜像。对中国用户，npm 是结构上更稳的那条路。

## 裁决

**v1 是一个运行时零第三方依赖的 npm 包，只有三个命令：`init`（筹备）、`check`（8 项守卫）、`update`（只刷新框架管理的文件）。规则真身是 AGENTS.md，CLAUDE.md 只留一行 `@AGENTS.md` 门牌。守卫逻辑住在包里，用户项目以兼容版本范围引用——维护者发一次新版，用户项目下次 CI 自动用上，无需任何人手动升级。**

## 被否决的方案

**「Claude Code 插件市场当主体」**：官方自动更新体验最好，但私有协议只覆盖一家宿主，对目标用户约一半无效；且第三方市场的自动更新开关默认是关的。降级为后续可选的增强通道，不是主体。

**「运行时从网页地址拉最新规则」**：装完后每次运行悄悄取远端内容，效果上「永远最新」，但这正是 2026 年供应链投毒的主通道（2026 年 2 月出现首批针对 AI 编码用户的协同投毒；一项抽查发现市面 36% 的技能文件含提示注入；动态内容对代码审查和扫描器不可见）。npm 版本化＋CI 兼容范围已足够接近「推一次、全网到货」，且每次变更留痕、可回退、可锁定。永不采用。

**「GitHub template 模板仓库」**：一键复制出新仓库，但复制完与上游彻底断开，后续所有改进与用户无关。零更新能力，不采用。

**「照搬上游全部约 30 个守卫」**：其中 6 个纯业务、15 个需按项目改造，对新项目第一天全是噪音；且上游守卫注释里的实测数字（缓存取舍、CI 耗时）是在那台机器、那个套餐上测出来的，照搬等于把别人的实测冒充通用结论——恰好违反这套框架自己「凭实测不凭感觉」的原则。v1 只收 8 个与项目形态无关的守卫。

## 不变量

1. 运行时零第三方依赖（只用 Node 标准库）。筹备队必须在任意网络环境下一条命令跑通，依赖树越深，失败面越大。
2. `guiju update` 与任何更新机制**永不改写** AGENTS.md 与 CLAUDE.md——店规是店主的店产，「背后实时更新」只覆盖工具与质检，不远程改任何人的规则。
3. 新增守卫的前提：挂着一次真实发生过的事故，且误报经过实测收敛（守卫误报多就会被关掉，比没有更糟）。
4. 本仓库永远能通过自己的 `guiju check` 与 `node --test`（吃自己的狗粮）；模板改动与代码同权，走同一条 PR＋守卫流程。
5. 失效条件：若 Claude Code 原生支持读 AGENTS.md，门牌机制随之删除而不是继续维护；若 npm 国内镜像同步时效恶化到小时级以上，分发通道按当时实测重估。
