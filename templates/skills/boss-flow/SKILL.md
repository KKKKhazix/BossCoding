# BossCoding 干活流程

1. 开工前读项目根目录的 AGENTS.md——规则文件、导师模式与红线都在里面，全程遵守。还没连远端（`git remote -v` 为空）的项目，按各步的【本地阶段】执行，其余照旧。
2. 从主干开一条新分支；一个任务一个分支一个 PR。并行的第二个任务起，用 `npx boss task <任务名>` 开独立工作区，别挤在主工作区里互相切分支（有 git hook 盯着）。
3. 改完先跑 `npm run preflight`（守卫＋测试）；红了先修，不带红提交。
4. 提交并开 Draft PR，正文写清改了什么、为什么。【本地阶段】没有 PR，提交都落在任务分支上即可。
5. 转 Ready 前跑 `npx boss merge`：退出码 0 才轮到你，1 就等前面那个先进（并行开发、串行合并）。【本地阶段】它会确认无需排队。
6. CI 绿后按项目规则合并；CI 红了先修复或撤销，不新增门禁。【本地阶段】preflight 绿后本地合并：`git checkout main && git merge <分支>`。
7. 收尾必给老板验收单，三样缺一不可：怎么打开看（命令或地址）、重点看哪三点、不满意怎么说。老板没验收，任务不算完。
8. 触碰规则文件红线的操作（删数据、对外发布、花钱、动密钥）：先说明、等老板确认，再动手。
