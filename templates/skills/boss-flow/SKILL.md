# BossCoding 干活流程

1. 开工前读项目根目录的 AGENTS.md——规则文件、导师模式与红线都在里面，全程遵守。拿不准项目当前状态就跑 `npx boss status`（只读），别读文档猜。
2. 从主干开一条新分支；一个任务一个分支一个 PR。并行的第二个任务起，用 `npx boss task <任务名>` 开独立工作区（它会顺带把依赖装好），别挤在主工作区里互相切分支。
3. 改完跑 `npm run preflight`（守卫＋测试）；红了先修，不带红提交。它报「命令找不到」＝依赖没装，先 `npm install` 再跑，**不要**改用别的命令绕过去。
4. 每次交付都要能回答「产品还能跑吗」：项目还没有冒烟测试（最小的一条自动验证）就先建一条，之后每次改动都跑。守卫查的是卫生，不是产品坏没坏。
5. 【本地阶段，`git remote -v` 为空】没有 PR：提交留在任务分支上，自检绿了本地合并 `git checkout main && git merge <分支>`。**一旦连上 GitHub，本步作废**，改走 6–8。
6. 提交并开 Draft PR，正文写清改了什么、为什么。
7. 转 Ready 前跑 `npx boss merge`：退出码 0 才轮到你，1 就等前面那个先进（并行开发、串行合并）。
8. CI 绿后按项目规则合并；CI 红了先修复或撤销，不新增门禁。
9. 收尾必给老板验收单，三样缺一不可：怎么打开看（命令或地址）、重点看哪三点、不满意怎么说。老板没验收，任务不算完。
10. 老板说「改坏了／退回去」：先问退到哪一版，用 `git log --oneline` 把候选点念给他听，再 `git revert` 撤销（保留历史，可再撤销）。永不用 `git reset --hard` 抹掉他的东西。
11. 触碰规则文件红线的操作（删数据、对外发布、花钱、动密钥）：先说明、等老板确认，再动手。
