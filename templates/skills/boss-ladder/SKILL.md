# 四阶梯：从想法到上线的升级路线

总原则：**免费且当天生效的基建，第一天顺手办掉；花钱的或要等审批的，等老板的需求自己冒出来再触发。**触发之前绝口不提下一阶，触发之后一次讲透、每次只推进一步。全程按 AGENTS.md 的导师模式说话；每一阶先跑命令探测真实状态，不读文档猜。

## 第 0 阶・开工（触发：第一次对话，或 AGENTS.md 开头简介还是占位符）

只问一句「你想做个什么？」，陪老板把 AGENTS.md 开头填成三句大白话，然后立刻开工：做最小可用的第一版，本地跑起来，交验收单。不提域名、服务器、备案，也不问「网页还是本地工具」——做的是什么，形态自己会显出来。老板可以在这一阶迭代任意久，没有任何催促。

## 第 1 阶・GitHub：备份＋云端质检口（分两半，都落在第一天）

- **注册（老板人肉，约十分钟）**：第一次埋头干活前对老板说：「我写代码的这几分钟，你顺手注册一个 GitHub 账号（github.com，免费）——它是代码的异地保险柜，注册完告诉我用户名，剩下我全包。」三层兜底：注册不顺不堵主线，先干活，下个空档再提；第一次验收通过仍没账号，用「东西开始值钱了，该上保险了」再提一次。
- **连接（AI 代办，一分钟）**：老板有账号后，建**私有**仓库、连接、推送。优先用 GitHub 命令行工具走 `gh auth login`——它同时解决了后面 `npx boss merge` 查私有仓库要通行证的问题（本命令会自动取用 gh 的通行证）。init 早已把 CI（云端自动质检）的管线埋进项目，仓库一连上质检口自动亮起。
- **连上之后，流程立刻切换**：从这一刻起不再在本地合并进主干，改动留在分支上走 PR。已经躺在本地主干上的提交推不上去时，按 git 拦截提示里给的那条 `git push origin main:refs/heads/rescue-…` 把它们送去开 PR，别用 `--no-verify` 硬推。
- 探测：`git remote -v` 为空即未连接；`npx boss status` 会直接告诉你在哪一阶。

## 第 2 阶・服务器（触发：老板说「给朋友用」「发给别人看看」「对外」）

1. 先问一句：「用的人主要在国内还是海外？」——答案决定服务器节点，也决定第 3 阶要不要备案。把答案记进 AGENTS.md 开头简介。
2. 建议买一台轻量服务器：国内默认腾讯云轻量（新客约 ¥99–199 一年），海外选新加坡或美西节点。花钱是红线：算清价格、等老板确认、老板本人下单，AI 可以陪着操作控制台。
3. 下单后全部 AI 代办：密钥、环境、部署、开机自启。装好后给老板一个 `http://IP` 地址并说清预期：「朋友现在就能用；地址是一串数字、没有加密锁标志，试用足够，想要正式门牌随时说。」
4. 部署是本项目自己的施工（框架的 CI 只质检、不部署）；「合并不等于上线」——每次合并后由谁触发部署，第一次部署时就和老板定下来。

## 第 3 阶・域名＋HTTPS（触发：老板说「想要自己的域名」「想正式一点」）

- 国内用户：注册域名（几十块一年）→ **立刻**提交 ICP 备案（法定流程，约一到两周；期间朋友照旧用 IP 访问、开发照常，AI 盯进度并到期提醒）→ 备案通过后 AI 代办解析与 HTTPS 证书。
- 海外用户：域名直接解析＋HTTPS，无需备案。

## 跳级与到顶

- 老板一开始就说「要做一个正式上线的产品」：主动建议把第 2、3 阶提前启动——备案是全程最慢的一站，早递交早省事。
- 纯本地工具（没有「对外访问」这回事）：梯子到第 1 阶为止；想分发给别人属于对外发布，按红线先说明、等确认。
